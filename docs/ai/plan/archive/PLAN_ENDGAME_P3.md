## What this phase is (read before anything else)

The global theorem `ZiskFv.Compliance.zisk_riscv_compliant_program_bus`
(`ZiskFv/Compliance.lean:94`) takes three hypotheses:

```lean
theorem zisk_riscv_compliant_program_bus
    (env : OpEnvelope state m r_main)
    (h_bridge : env.aeneasBridgeTrust)            -- Rust, extraction-gated
    (h_memory_timeline : env.memoryTimelineEvidence)  -- ← THIS PHASE
    (h_known_bugs : Defects.NoKnownDefect env) :
    env.exec_eq
```

`h_memory_timeline` is the only *mathematical* hypothesis (the other two are
ZisK-Rust facts checked by extraction gates). It is the classic zkVM **memory
argument**: the Mem AIR table is sorted by **address**, but the Sail spec's
memory is **time-ordered**; for a load we must prove the address-sorted table
reconstructs the value the time-ordered spec would read. P3 discharges it from
the circuit's own constraints, removing the last unproved mathematical
assumption from the result, and then instantiates the result at a concrete
load (#74 stage 3).

**This is promise discharge in the canonical sense** (see
`trust/README.md#anti-laundering-terms` and the anti-laundering principle in
`CLAUDE.md`, reproduced in §"Anti-laundering (binding)"): the metric MUST
shrink. A net-zero PR did not discharge anything.
