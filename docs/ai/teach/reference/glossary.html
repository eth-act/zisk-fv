Build & generation how inputs are produced

Nix flake / flake.lock
Reproducible build definition; flake.lock pins every input by content hash — the audit surface for build inputs. flake.nix, nix/
nix run .#populate
Builds the generated derivations and copies outputs into the tree. Run once before lake build.
PIL / PIL2 · .pilout
ZisK's constraint DSL; the pil2-compiler composes all AIRs into build/zisk.pilout (protobuf, 22 AIRs).
pil-extract
Rust tool: reads .pilout and emits per-AIR Lean constraints (air mode → gitignored build/extraction/) and committed Clean components (clean-component mode → AirsClean/). tools/pil-extract
Aeneas
Rust→Lean extraction of ZisK's production lowering (on the zisk/ submodule), backing the completeness harness and the aeneasBridgeTrust hypothesis.

Circuit / AIR — the RHS what ZisK computes

AIR (Algebraic Intermediate Representation)
One circuit's constraint set. ZisK has ~22 AIRs; ~10 are on the RV64IM path (Main, Binary, BinaryAdd, BinaryExtension, Arith, Mem, MemAlign…).
Valid_<AIR>
A Lean record of named columns + simp lemmas wrapping an AIR, mirroring its PIL constraints. Constructibility risk lives here (over-strong ⇒ vacuous). ZiskFv/Airs/
Operation bus / matches_entry
The model for how an instruction maps to circuit rows; replaces explicit interaction tracking. Airs/OperationBus
Goldilocks / FGL
The field (p = 2⁶⁴ − 2³² + 1); FGL is the Lean Field instance. ZiskFv/Field/Goldilocks.lean
Clean / AirsClean
The Clean ZK-circuit DSL; AirsClean/ holds generated Row/Constraints + hand-written Circuit/Spec/Soundness/Bridge. ZiskFv/AirsClean/ (74)
validOfRow
The bridge lowering a Clean row into the legacy Valid_<AIR> record — so AirsClean feeds, not replaces, Airs. AirsClean/<AIR>/Bridge.lean

Spec — the LHS the reference truth

Sail · execute_instruction
The official RISC-V spec language; sail-riscv compiled to Lean is the LHS reference. execute_instruction maps a decoded instruction + state to the next state. build/sail-lean/
Pure spec
Per-opcode bridge files restating Sail semantics in proof-friendly form. ZiskFv/SailSpec/

Proof tower where LHS meets RHS

EquivCore/<Op>
The real per-opcode proof: Sail.execute = bus_effect.2, given a well-formed AIR row. ZiskFv/EquivCore/ (95)
Promise hypothesis
A caller-supplied assumption a theorem takes as a parameter instead of proving — the residual trust. (The new top, below, discharges many of these from a trace.)
Wrapper / Compliance.equiv_<OP>
Discharges the AIR-row/table facts from the provider's Valid_ spec. ZiskFv/Compliance/Wrappers/
equiv_<OP> (canonical)
The 63 public per-opcode theorems in channel-balance form; OUTPUT-EQ-free by gate. ZiskFv/Equivalence/ (63)
OpEnvelope
A 63-arm inductive; each constructor carries an opcode's data + promises as fields. ZiskFv/Compliance/OpEnvelope.lean
zisk_riscv_compliant_program_bus
The OLD headline. Given an OpEnvelope + 3 hypotheses (aeneasBridgeTrust, memoryTimelineConstruction, NoKnownDefect), proves the channel-balance conclusion. Conditioned: the envelope is assumed. ZiskFv/Compliance.lean:95

Trace-level top new builds what the old top assumed

construction_<op>_sound
Per-opcode theorems that construct the inputs (build the envelope / step compliance) rather than assume them. 20 Construction* modules. ZiskFv/Compliance/Construction*.lean
AcceptedTrace · ProgramBinding
An accepted full-ensemble trace and its program binding — the input the trace-level export reasons over (in place of a hand-built OpEnvelope).
StrongRowConstructionData
A sum type, one arm per opcode; each arm packages that construction's genuinely-irreducible residual binders (decode pins, Sail reads, operand/lane bridges, exec-row facts; loads also add memory-timeline evidence). It does NOT package op-bus provider-match evidence — that's derived from trace.balanced. TraceLevelExport.lean
root_soundness
The NEW headline. Given an AcceptedTrace, a binding, a per-row StrongRowConstructionData classification, and per-row defect-exclusion (h_known_bugs), proves every row satisfies the channel-balance conclusion — with no caller-supplied OpEnvelope. Covers all 63 archetypes via 3 routes; 0 project axioms. ZiskFv/Soundness.lean:21
The three routes
(1) Env-constructed — 22 op-bus ALU arms: envelope built from the trace, fed to the old global theorem, 3 hyps discharged in place. (2) Direct-lift — 27 control-flow/U-type/load/store/unsigned-M arms: lift construction_<op>_sound's bus_effect form to channel-balance via defeq. (3) Defect-narrowed — 7 signed-M arms + FENCE, gated by h_known_bugs.

Trust gate guards the claim

Trust gate
Two layers: V1 syntactic (check-all.sh, no build) + V2 semantic (check-all-semantic.sh, needs oleans). trust/scripts/
Trust ledger
The recorded trusted axioms + source-text hashes; currently 0 axioms. trust/generated/baseline-axioms.txt
Caller-burden ledger
One line per binder on every canonical theorem; the diff is the audit surface (a real discharge removes more than it adds).
Strong-export gates new
check-strong-export-closure.sh + check-strong-export-binders.sh pin the trace-level export's axiom closure (expected empty) and exact binder list; check-construction-theorem-binders.sh deep-renders the construction theorems' binders. trust/generated/baseline-strong-export-*.txt
Constructibility / anti-laundering
Over-strong Valid_<AIR> ⇒ vacuous theorems; the hypothesis-count + caller-burden baselines must shrink, not just move trust around.
Defects.NoKnownDefect / trust/defects.md
The known-defect carve-out (e.g. the DIV/REM signed remainder-bound bug). "Compliant" means "modulo known defects."

Completeness the coverage side

root_completeness
An acceptance/coverage theorem: every Sail-executable RV64IM word (outside the FENCE decode gap) is accepted by the production ZisK path; Aeneas-gate mediated. ZiskFv/Completeness/Rv64im
