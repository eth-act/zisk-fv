This is a very large formal verification project for a zero-knowledge virtual machine based on RISC-V, which is called Zisk, Z-I-S-K. It's been built over the course of months using general purpose coding agents such as Claude and Codex, and it seems to have made quite good progress. It's found many bugs, though I'm aware that there are bugs that exist that it did not identify due to its current limitations. I think the project is workable, but it's not designed well, and this applies at multiple levels. First of all, it's taken a lot of work to get to a reasonable audit surface where, for an audit, we want to look at what I call the root theorems, and in this project there are to be two: root underscore soundness and root underscore completeness. Currently, the soundness theorem is reaching an MVP status, and the completeness theorem is merely a work in progress. What I would like to know is how how to redesign the API in terms of the top-level theorems for maximum explicitness and readability, and secondly, I would like to know how to better architect the proofs for maintainability. I have put very little effort into looking at the proofs, and I'm nearly certain that they are somewhat opaque and not making use of reusable abstractions. In particular, the library called Clean that we use as a compilation target for the circuits is almost surely not being used in an idiomatic fashion. I've only started to look at this code in any depth recently, and I've only looked at the top layers, so I can't be more specific than this. But what I want for you to do is to deeply understand the clean idioms, understand what the core recurring patterns are in this, understand the architecture and look for questionable divergences and inconsistencies, and then suggest a comprehensive refactor of this code to be beautiful, auditable, comprehensive, maintainable, extensible, and most importantly, correct.
